# 设计实施说明

日期：2026-10-04｜桌面 A 已选｜手机原型 2.1，M1/M2 待最终选择

## 设计依据

个人图片工具以找图、处理、发布与回访结果为核心。图片占据主要视觉面积，文字与状态有明确层级；使用克制中性色、蓝色主动作和有文字说明的语义状态，避免装饰大图、营销首屏与无用途的统计卡。

M1「图库优先」使用图库/链接/任务三个稳定目的地；选图后的处理和上传是上下文动作。M2「发布工作台」从一次发布批次出发，按选图、可选处理、确认上传对象推进，无底栏。两者不是换色方案：起点、返回路径、草稿入口和结果回访结构不同。

原图、临时处理结果、永久保存副本、导出与远端成功各自具有状态。详情、任务和链接必须引用同一版本×目标结果；名称和扩展名不能靠当前编辑器参数猜测。

参考入口：[Android 导航与布局](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns?hl=en)、[Apple Photos 编辑](https://support.apple.com/en-ae/guide/iphone/iph2413db0ab/ios)、[Lightroom 导出](https://helpx.adobe.com/nz/lightroom/mobile/share-save-and-export/export-photos-in-multiple-formats.html)。这些是设计阅读资料；没有继承其云账户、专业编辑、品牌资产或整库同步能力，也没有效率/商业成功的实测结论。

## 使用资源时的优先级

1. 正式需求决定业务规则、数据行为、分期和验收；技术文档决定实现职责与依赖。
2. 本包当前手机规格决定共同交互规则，桌面 A 样本决定已选桌面布局；桌面历史行为不足的部分按正式需求补齐。
3. HTML/CSS 为可观察的视觉与流程样本，不是 Flutter 组件库或生产应用代码。不能继承其临时状态、固定时间、示例容量、凭据字符串、假处理结果和固定网络回调。
4. Figma [既有文件](https://www.figma.com/design/ZZNCFyIONSibWLmRj2yexD) 尚未同步最新状态，不能优先于本包；没有将其当成新项目的强制依赖。

## 新项目必须真实实现的部分

独立永久副本、事务/文件提交与中断恢复、持久草稿/队列、真实像素处理、格式/动画/方向/元数据行为、导出/系统照片权限、受保护凭据、真实图床、备份恢复、清理引用保护，以及四端后台限制。具体范围与验收不在这里另造规则，逐条遵循需求1.1。

原型会话内保存选图、参数、结果和草稿，刷新会重置。所有上传、保存、导出、备份、诊断和剪贴板反馈均模拟；不得以浏览器演示成功声称这些生产能力已完成。

## 素材与原型边界

两个样本共享唯一的九宫格合成图片，来源见 [素材说明](assets/asset-source.md)。它不是九张真实格式文件，示例 JPEG/PNG/WebP/BMP 名称与尺寸只是设计夹具；不能拿它验证图片格式、哈希去重或编解码能力。

原型 SVG 图标嵌在各自 JS 中，未使用第三方产品商标或图标包。正式 Flutter 中可以按选型实现语义图标，必须保留可访问名称和触控容器。44 CSS像素是原型检查条件，不等同各原生平台实际触控/缩放验收已通过。
