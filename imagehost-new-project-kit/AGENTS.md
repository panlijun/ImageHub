# ImageHost 新项目实施约定

本文件用于全新项目；若新工作区已有 AGENTS.md，合并必要约束而不是覆盖其他约定。用户当前明确指令优先。

- 默认中文，范围以本包需求与用户后续决定为准。先读取真实实现、未提交修改及已有约定，再做修改。
- 独立新建 Flutter/Dart 四端实现；不继承旧 Tauri/React/Rust 架构，不读取旧应用数据库或迁移旧数据。本包 documents 中的旧路径只为需求来源追踪。
- 以 documents/requirements-analysis.md（1.1）决定业务及分期，technology-selection.md（1.0）决定已选技术。技术文档核查日期不等于依赖锁定；初始化时核验同一套稳定依赖的实际兼容性，再固定 SDK 和锁文件。
- 桌面 A 已选；手机 M1/M2 尚未选择。先实现共同业务，候选导航不能混用。不得以开发者偏好替用户做最终手机选择。
- design 中 JS/CSS/HTML 为模拟设计资源，不复制其状态模型、内存持久化、示例账号、固定图片元信息或历史算法为生产实现。
- 个人使用可以简化运营和部署；不能省略 V1 的 P0/P1、永久副本、清理引用保护、失败原子性、任务恢复、备份校验或凭据保护。
- ProviderAdapter、图片处理、文件保管、队列、持久化及 UI 分离。结果按图片版本 × 稳定目标身份保存；名称可重复，身份不复用。上传与应用云同步分开。
- 当前未选择/未验证的 SDK 精确版本、平台能力和格式支持必须留有验证结果，不根据包名或平台标签假设四端功能完全一致。
- 新需求或业务矛盾先修需求/决策，再改实现与测试；原型表现和测试预期不得自行创造需求。版本变更同步 Markdown 与 Word；按用户既有约定核验内容与结构，未做逐页视觉验收时如实注明。
- 所有 V1 需求必须映射到实际验证。flutter analyze、单元测试、契约/集成、权限/后台/编解码/真实网络和四端设备验收分别记录。一个平台或模拟依赖通过不能替代其他平台实测。
- 非秘密本地夹具与替身优先；真实图床测试应使用用户明确授权的测试账号和测试图片，不读取私有照片或输出秘密。健康检查无官方安全接口时显示未验证，不偷偷上传探测。
- flutter format/analyze/test 等命令按初始化后的真实项目确定，在项目级约定记录准确命令。不存在测试文件时不能报告测试通过；失败不得通过改无关代码消除。
- 无明确要求，不创建提交、推送或 PR。安装、大型下载、系统配置、部署、签名发布、开通云资源等外部动作需遵守用户许可。
- 首版不创建 Supabase 资源、不初始化云登录/同步，不接入 Cloudinary、Web/Linux 或团队功能。后续范围按正式分期和用户指令开启。
